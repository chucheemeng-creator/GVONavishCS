# 發現物同步（GVODiscoverySync）

讀《大航海時代 Online》的「發現物一覽」畫面，自動在安瑟兒的發現物統計 Excel 幫角色打勾。

只看遊戲畫面（和 GVONavish 讀座標一樣），**不讀取、不修改遊戲記憶體，也不會對遊戲按任何按鍵或滑鼠**。

## 系統需求

- Windows 10（2004 以後）/ 11
- [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)
- **繁體中文的文字辨識**：Windows「設定 → 時間與語言 → 語言與地區」新增「中文（繁體，台灣）」，語言選項裡要有「光學字元辨識」。程式啟動時會檢查，沒有的話會提示。
- 安瑟兒的發現物統計表（.xlsx）

## 用法

1. 按「選擇…」選 Excel 檔案，選要打勾的人物（名稱取自 Excel 首頁第 2 列）。
2. 遊戲裡打開「發現物」→ 選一個分類 →「一覽顯示」。
3. 按「開始讀取」，在遊戲裡把清單從頭捲到尾（按 ▼ 或滾輪都可以）。每次畫面停下來就讀一次，讀過的不會重複。
4. 換下一個分類，一樣捲一遍。
5. 檢查清單：
   - **新增**：會寫入（可以取消勾選）。下面的「新增」數字是目前勾選、會寫入的筆數，「不確定」「推斷」的列確認後打勾也算進去
   - **推斷，請確認**：整列讀不出來、由前後列推斷出來的（相似度欄顯示「推斷」），預設不寫入，確認後自己勾選
   - **已經打勾**：Excel 裡本來就有勾
   - **不確定，請手動指定**：好幾個名稱一樣像（例如漏讀成「天座」，「天○座」有十幾個），程式不猜，
     「Excel 上的名稱」欄顯示幾個字、在哪兩列之間，請按右鍵「指定 Excel 發現物」選
   - **不確定（請確認）**：同名的一組等情況，預設不寫入，確認後自己勾選
   - **同名，請確認**：遊戲上同名、Excel 用數字區分的（例如「聖母加冠1」「聖母加冠2」），分不出是哪一個（只有同一頁同時看到全部、或依價值排列時用功績判斷出來的，才算確定）
   - **找不到**：Excel 裡沒有對應的名稱（辨識錯字、或是新版本的發現物），請手動處理
   - **讀不出來，請手動確認**：這一列有字但怎麼讀都讀不出來，Excel 名稱欄會寫它在哪兩個發現物之間
   - **手動修正**：在任何一列按右鍵 →「指定 Excel 發現物…」（或選取後按 Enter），從清單挑正確的發現物；
     依和畫面文字的相似度排序，可以打字搜尋，分類判斷錯了也能換；列出 ★、任務／地圖幫忙判斷。
     這一列已經有對到或推斷的結果時，開啟時會捲到它並選好（狀態欄顯示「目前的結果」），沒錯的話直接按確定。選好後是「新增（手動指定）」。
     辨識出來的垃圾列按右鍵 →「移除這一筆」（或按 Delete）。手動處理過的列，繼續捲動時再讀到也不會加回來。
   - **複製讀到的原文**：右鍵 →「複製遊戲畫面上的名稱」（或 Ctrl+C／Ctrl+Insert，可以多選），常讀錯的字可以直接貼進錯字對照表。
6. **關閉 Excel**，按「寫入 Excel」。寫入前會把原檔備份到 Excel 所在資料夾的 `backup\`（`檔名.bak-日期時間.xlsx`）。

> 本程式的視窗不要擋住遊戲的清單，否則會截到自己的視窗。
> 按 **F1** 切換視窗置頂（遊戲在前面時也看得到本程式），會記住下次開啟時的狀態。

## 怎麼辨識的

- **影像處理**：清單每一列各自找出底色，轉成白底黑字、放大 3 倍再交給 Windows 的文字辨識；先用 3 倍讀一次，每一列都和 Excel 的名稱完全一樣就不再讀；有讀錯、讀不出來的列，再用 2.5、3.5 倍各讀一次，每一列挑最像 Excel 名稱的結果（除錯輸出一律三種倍率都讀，看得到每種倍率的結果）。
- **分類**：先讀左上角的分類標題；標題只有兩、三個字，常常讀不出來，這時從清單上的名稱推測是哪個分類。
- **比對**：名稱用模糊比對，對漏字特別寬容（辨識最常見的錯是漏掉筆畫密的字）。
- **字數**：清單的字型每個中文字一樣寬（16 遊戲像素），所以從畫面上量這一列的字有多寬，就知道名稱原本有幾個字。字數對不上的名稱不列入比對，例如讀到「鳳蝶」、畫面上是四個字寬，就不會被當成「黑鳳蝶」。讀到的字和某個名稱完全一樣、字數卻對不上時（例如「三聖像」漏讀成剛好存在的「聖像」），標成不確定。除錯輸出的 txt 每一列會顯示量到的寬度和大約幾個字。整列讀不出來的（多半是一、兩個字的短名稱）也用字數推斷：例如昆蟲類一個字的名稱只有「蠶」，量到一個字寬就推斷是它（顯示「推斷，請確認」）。
- **比對字形**：遊戲的字是點陣字，同一個字每次出現的點完全一樣。讀到的字和 Excel 完全一樣的列，程式會順便記下每個字的字形。程式內建 1,845 個字的字形，所以一開始就認得大部分的字；另外學到的存在 `GVODiscoverySync.Glyphs.json`（程式自己維護，不用改；可以複製到別台電腦；刪掉會重新學）。
  之後遇到讀不出來、讀錯的列，認得的那幾格等於已經讀出來了（例如「南非兀？」）。這個分類裡字數相同、和這些格子不矛盾的名稱只剩一個時：
  - 每個字都認得，或還有不認得的字、但文字辨識的模糊比對也指向同一個名稱：確定是它（狀態顯示「新增（字形比對）」），後者順便學會不認得的字。
  - 還有不認得的字、文字辨識也沒讀出來：顯示「推斷，請確認」。
  - 模糊比對對到的名稱如果和字形矛盾，不採用。

  手動指定、或勾選後寫入 Excel 的列也會學起來，所以文字辨識永遠讀不對的字（「蠶」「玫」），確認一次以後就認得。越用認得的字越多。
  同一個字在遊戲上有兩種字形時（例如「彗」），程式學到新的那一種之後，舊的會留作「另一種字形」，兩種都認得。
  Excel 和遊戲用的字不一樣時（Excel 寫「阿閦如來」，遊戲上是「阿閦如来」），那一列的字形會和名稱矛盾，顯示「不確定，請手動指定」。按右鍵「指定 Excel 發現物」選一次之後，程式會把那一格記成那個字的另一種字形，以後就認得（至少要有一個字對得上，而且對不上的字最多一個，免得指定錯了把字形表弄亂）。
  除錯輸出的 txt 每一列會顯示〔字形：…〕，不認得的格子是「？」。
  遊戲畫面被 Windows 放大顯示（150% 以上）時畫面是糊的：程式在每個遊戲像素的中心取樣，換成「最像的已知字形」再比對。這樣不是逐點精確的，所以只在整列每個字都認得、而且只有一個名稱對得上時採用；不用來排除、推斷，也不學新的字（新的字要在 100% 的電腦上學，再把 `GVODiscoverySync.Glyphs.json` 複製過來）。125% 時筆畫太糊，不比對字形，其他功能照舊。
- **Excel 和遊戲寫法不同的名稱**：Excel 為了和別的分類區分加了註記的，比對時用遊戲上的寫法，例如港口類的「關島(港)」在遊戲上是「關島」（地理類也有一個「關島」）。寫入時照樣寫到 Excel 的那一列。對照表放在 `GVODiscoverySync.NameAliases.json`，見下面的「名稱對照表」。
- **同一頁推斷**：同一頁每一列都是不同的發現物；清單照名稱的字元編碼排序時（預設的排序），每一列一定排在上下兩列之間；依價值排列時，功績一定介於上下兩列之間。用這幾點排除不可能的候選。
  遊戲改版有時會調整功績、Excel 不一定跟著改，這一頁的功績和 Excel 對不上時（排序看不出來），刻意不推斷，讓使用者自己確認。
- **排序方式**：每一頁判斷是「依價值」（功績由高到低）還是「依名稱」（字元編碼由小到大）排列。證據充分的頁面（至少 4 個已確定的列、只符合其中一種）會記住排序方式，發現物少、證據不足的頁面沿用它；兩種都符合時不下判斷，免得誤判。用只有 1%～3% 發現物的新手資料模擬過，沒有判斷錯的情況。
- **同名的發現物**：遊戲上同名、Excel 用數字區分（例如「水鹿」「水鹿2」）。依價值排列時用上下鄰居的功績判斷是哪一個（同名的各個功績都不同）；另外記住每一個的上下鄰居，鄰居不同就是不同的一個，所以分散在不同頁也數得出來。

## 錯字對照表

文字辨識固定會讀錯的字（例如「鑽」每次都讀成「巑」、「海」拆成「冫每」），放在程式資料夾的 `GVODiscoverySync.OcrConfusions.json`，左邊是讀到的、右邊是正確的。比對時照原樣、換字後各比一次，取比較像的，所以原本就有這個字的名稱不受影響。

- **程式開著也可以改**：存檔後，下一次讀取畫面時就會換成新的對照表，目前這一頁也會重新讀一次。格式寫錯時狀態列會提示，並繼續用原本的對照表。
- 這個檔案程式只在第一次（檔案不存在時）建立，之後只讀不寫，所以改好的內容不會被蓋掉。舊版放在 `GVODiscoverySync.json` 的 `OcrConfusions` 會自動搬過來。
- 內建的錯字沒寫在檔案裡也會使用。不想用某一組內建的，把它改成對應到自己（例如 `"專": "專"`）。
- 讀錯的字可以在清單上按右鍵「複製遊戲畫面上的名稱」複製出來。

## 名稱對照表

Excel 和遊戲寫法不同的名稱，放在程式資料夾的 `GVODiscoverySync.NameAliases.json`，左邊是 Excel 上的寫法、右邊是遊戲上的寫法：

```
{
  "關島(港)": "關島",
}
```

- Excel 改版後遇到新的（讀得到字、卻一直「找不到」，Excel 裡的名稱多了註記），自己加一行就好，不用等新版程式。
- 左邊要和 Excel 一字不差，括號的全形、半形也要一樣；寫錯不會有提示，只是沒有作用。
- 和錯字對照表一樣：程式開著也可以改，存檔後下一次讀取畫面就套用；程式只在檔案不存在時建立，之後只讀不寫；內建的沒寫在檔案裡也會使用。

## 筆電、放大顯示的電腦（Windows 顯示縮放不是 100%）

Windows 的「顯示縮放」設成 125%、150% 時，遊戲畫面是被系統拉大的，字的邊緣會糊掉。程式照樣能用，但「比對字形」的能力不同：

| 顯示縮放 | 文字辨識、推斷 | 認字（比對字形） | 學新的字 |
|---|---|---|---|
| 100% | ✔ | ✔ | ✔ |
| 150% 以上 | ✔ | ✔（只在整列每個字都認得時採用） | ✘ |
| 125% | ✔ | ✘ | ✘ |

- **150% 的電腦只認字、不學字**：程式內建 1,845 個字的字形，這些字在 150% 的電腦上一樣認得。但糊掉的畫面學不到精確的字形，所以遇到內建沒有的字，不會像 100% 的電腦那樣「確認一次以後就認得」，那幾列每次都要靠文字辨識、推斷，或手動指定。
- **想讓 150% 的電腦認得更多字**：在一台 100% 的電腦上掃過、確認過之後，把那台電腦程式旁邊的 `GVODiscoverySync.Glyphs.json` 複製到這台電腦的程式旁邊。也可以請已經學過的朋友給你這個檔案。
- **怎麼知道自己是多少**：不是 100% 時，程式讀到一頁後狀態列的最後會顯示〔顯示縮放 150%：字形只認不學〕或〔顯示縮放 125%：不比對字形〕；「存下遊戲畫面」的檔名裡也有（`-s1` 是 100%、`-s1.5` 是 150%）。
- 這不影響寫入 Excel 的正確性：認不出來的列只是顯示「讀不出來」「推斷，請確認」，要你自己確認，不會被當成確定。

## 讀不準的時候

按「存下遊戲畫面」，程式資料夾的 `screens\` 會存下四個檔案（檔名帶縮放倍率，例如 `-s1.5`）：
- `….png`：遊戲畫面原圖，之後可以用「用截圖檔測試…」重讀
- `…-title.png`、`…-list.png`：辨識前處理好的分類標題和清單
- `….txt`：每一列讀到的原文，和比對到的 Excel 名稱

設定檔 `GVODiscoverySync.json` 也在程式資料夾（從 Visual Studio 執行時是 `bin\Debug\net10.0-windows10.0.19041.0\`）。

清單位置存在 `GVODiscoverySync.json` 的 `Layout`（遊戲原本的像素，相對於遊戲畫面正中央）。實測可用的環境：800 × 600 ＋ 顯示縮放 100%、800 × 600 ＋ 150%、1280 × 720 ＋ 100%。
